Embedding Python
macros - 26.08.2010 20:26, Сообщений - 39
Здравствуйте!

Есть идея вставить интерпретатор языка Python в SBCL.  Насколько это нужно -- вопрос отдельный, но, по-видимому, доступ к библиотекам Python может пригодиться в определённых ситуациях. Например, Python имеет выход на некоторые C++ билиотеки, а как привязать эти билиотеки к SBCL, непонятно. Нужен отдельный binding к C++. Безусловно, логику приятнее писать на Lisp, но бывает, что нужна какая-нибудь утилита (тот же XML-парсер), которую очень удобно использовать в Python, а в Lisp (по крайней мере в стандартной комплектации stable Debian) аналогичная программа либо вообще отсутствует, либо сильно уступает по функциональности.  А так можно использовать "лучшее из двух миров" :)

Вопрос у меня возник по дизайну. Как сделать API универсальным?  Возможно, эти проблемы типичные  и уже кем-то решались:

1) Передача произвольного  (но разумно ограниченного) числа аргументов,
2) Передача аргуметнов разных типов и разной структуры (одиночные значения, массивы, структуры, массивы структур и т.п.,
3) Управление памятью,
4) То же что в пп 1-2 для получения результата выполнения функции Python

Есть мысль сделать некий универсальный "контейнер" (структуру) на C для обмена данными, абстрагировать  API на Lisp-е, но насколько это практично пока неясно.
В общем, буду рад любям замечаниям, предложениям.

[#]
> Речь идёт лишь об обмене данными.

Когда в проекте пишут на двух разных (в данном случае - очень разных) языках, то обычно используют независимые средства обмена данными, а не скрещивают эти языки :) Можно использовать файлы, можно использовать сообщения.

> 1) Передача произвольного  (но разумно ограниченного) числа аргументов,
> 2) Передача аргуметнов разных типов и разной структуры (одиночные значения, массивы, структуры, массивы структур и т.п.,
> 3) Управление памятью,
> 4) То же что в пп 1-2 для получения результата выполнения функции Python

Всё это сложно - нужно подключать libpython импортировать весь C-API и после этого совершать преобразования lisp-data <-> python-data, т.е. по сложности это примерно как реализовать alien-ы, кроме того это потребует использования колбеков, которые в SBCL не очень стабильны на данный момент. Вообще вот - http://docs.python.org/extending/embedding.html

Самое простое что можно сделать, ето заставит работать python-eval:

;;;
;;; How to embedding Python into Common Lisp runtime.
;;;
;;;  For more information see:
;;;
;;;  -*- http://docs.python.org/extending/embedding.html
;;;
;;;  -*- http://docs.python.org/c-api/
;;;

(eval-when (:compile-toplevel :load-toplevel :execute)
  (asdf:oos 'asdf:load-op :cffi))

(defpackage #:py
  (:use     #:common-lisp
            #:cffi)
  (:shadow  #:eval)
  (:export  #:eval))

(in-package #:py)

;;; Utils

(defmacro many (macro &rest forms)
  "Map MACRO to FORMS."
  `(progn ,@(loop :for form :in forms :collect `(,macro ,@form))))

;;; Python Shared Library

(define-foreign-library libpython
  (:darwin  (:framework "Python"))
  (:unix    (:or "libpython2.6.so.1.0"
                 "libpython2.5.so.1.0"
                 "libpython2.4.so.1.0"
                 "libpython2.3.so.1.0"))
