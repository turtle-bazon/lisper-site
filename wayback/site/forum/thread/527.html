Если же "generate" перенести в "packet-1", то ничего этого не требуется.

Если появляется какая-то непонятка с макросами, полезно посмортеть результат их раскрытия с помощью macroexpand. В данном случае будет такая шняга:

PACKAGE-2> (macroexpand-1 '(generate                                            
              (format t "Some function called~%")))
(DEFUN PACKAGE-1::SOME-FUNCTION (PACKAGE-1::ARG)                                
  (FORMAT T "Some function called~%"))

Вызов generate раскрывается с использованием символа some-function из пакета packet-1, т.к. он был введен именно в том пакете в момент определения макроса generate. Чтобы иметь возможность работать с generate из любого пакета, вероятно придется воспользоваться intern:

(in-package :package-1)

(defmacro generate (&body body)
  `(defun ,(intern (string 'some-function)) (,(intern (string 'arg)))
      ,@body))

(in-package :package-2)

(macroexpand-1 '(generate                                            
              (format t "Some function called~%")))
(DEFUN SOME-FUNCTION (ARG)                                
  (FORMAT T "Some function called~%"))

Можно упростить задачу, например так:
(defmacro generate (&body body)
  (flet ((sym (string-design) (intern (string string-design)))
    `(defun ,(sym 'some-function) (,(sym 'arg))
        ,@body)))
Тогда в случае большого количества символов будет меньше писанины.
ЗЫ. не исключаю, что изобрел велосипед и есть более адекватные способы решения проблемы.

Символы создаются ридером при чтении кода и помещаются в текущий пакет. Применительно к макросам очень важно понимать, что макросы работают не с текстом, а именно с s-выражениями и уже имеющимися символами.

Вот оно - последний шаг, до которого не дошел. Фактически, все есть символ - переменная, имя функции, аргумент. Просто он получает соответствующее значение в соответствующем слоте в нужный момент. То есть, все аргументы всех функций в пакете есть отдельные символы внутри пакета, просто они не экспортируются.
