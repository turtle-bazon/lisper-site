Лиспификация идентификаторов¶

В шаблонах Closure Templates для именования пространств имён, шаблонов, параметров и переменных принято использовать CamelCase стиль. Поскольку данное соглашение не является естественным для Common Lisp, то Common Lisp backend cl-closure-template производит автоматическую "лиспификацию" всех используемых идентификаторов, например:

CL-USER> (closure-template:lispify-string "userName")
"USER-NAME"

CL-USER> (closure-template:lispify-string "closureTemplate.Example")
"CLOSURE-TEMPLATE.EXAMPLE"

Кроме того, все идентификаторы становятся символами (для параметров и переменных используются keyword-ы).

Компиляция¶

Компиляция файла с шаблонами Closure Templates осуществляется с помощью функции closure-template:compile-cl-templates и происходит по следующей схеме:

  1. Вызывается функция closure-template:ensure-ttable-package с лиспифицированным именем пространства имён. Если package с таким именем не существует, то он создаётся и в этом пакете создаётся специальная переменная namespace:*package-ttable*, в которой будут храниться все скомпилированные шаблоны.

  2. Для каждого шаблона создаётся замыкание, реализующее логику шаблона и регистрируется в карте namespace:*package-ttable*, в качестве ключа используется символ созданный на основе лиспфицированного имени шаблона.

  3. Вызывается функция closure-template:ttable-extend-package, которая для каждой пары (имя-шаблона . код-шаблона) связывает символ с замыканием с помощью setf symbol-function

Таким образом, в коде на Common Lisp к скомпилированным шаблонам можно обращаться как к простым функциям, например, имея скомпилированный шаблон

{namespace examples.simple}

{template helloName}
  Hello {$name}!
{/template}

Можно выполнить такой код:

CL-USER> (mapcar #'examples.simple:hello-name
                 '((:name "Ana") (:name "Bob") (:name "Cid") (:name "Dee")))
("Hello Ana!" "Hello Bob!" "Hello Cid!" "Hello Dee!")

Кроме того, с помощью closure-template:ttable-call-template можно также вызывать шаблоны используя их строковое имя и объект namespace:*package-ttable* (который уникален для каждого создаваемого package), например:

CL-USER> (closure-template:ttable-call-template examples.simple:*package-ttable*
                                                "HELLO-NAME"
                                                '(:name "Ana"))
"Hello Ana!"

В некоторых случаях такой способ вызова шаблонов может увеличить гибкость создаваемого приложения.

Использование прототипов¶

Функция closure-template:ensure-ttable-package имеет key-аргумент :prototype, который позволяет указать прототип для создаваемого объекта класса closure-template:ttable, который используется инициализации значение переменной namespace:*package-ttable*. На этом основана возможность "наследования" пространств имён Closure Templates в Common Lisp.

Скажем, если мы уже скомпилировали файл с пространством имён myapp.view.base:

{namespace myapp.view.base}

{template helloWorld}
   Hello world!
{/template}

{template mainPage}
   <h1>{call helloWorld /}</h1>
{/template}

Мы можем теперь выполнить:

(closure-template:ensure-ttable-package
  '#:myapp.view.mytheme
  :prototype (closure-template:package-ttable '#:myapp.view.base))

И скомпилировать файл с пространством имён myapp.view.mytheme:

{namespace myapp.view.mytheme}

{template helloWorld}
   Brave New World!
{/template}

Таким образом, пространство имён myapp.view.mytheme наследует myapp.view.base, но при этом переопределяет шаблона helloWorld. В этом легко убедиться следующим образом:

CL-USER> (myapp.view.base:main-page)
"<h1>Hello world!</h1>"

CL-USER> (myapp.view.mytheme:main-page)
"<h1>Brave New World!</h1>"

Подготовка данных для передачи в шаблон¶

Примитивные типы Common Lisp непосредственно отражаются на примитивные типы Closure Templates и данные этих типов не требуют какой-либо подготовки при передаче в шаблон.

Для использования в качестве списков Closure Templates могут использоваться объекты Common Lisp list и array.

Для использования в качестве словарей Closure Templates могут быть использованы любые типы Common Lisp, для которых реализованы generic-методы closure-template:fetch-keys и closure-template:fetch-property. cl-closure-template содержит в себе реализацию этих методов для plist, alist, hash-table, а также для стандартных объектов CLOS. Ниже несколько примеров с использованием ранее определённого шаблона examples.simple:hello-name:

Использование в качестве словаря plist:

CL-USER> (examples.simple:hello-name '(:name "Ana"))
"Hello Ana!"

Использование в качестве словаря alist:

CL-USER> (examples.simple:hello-name '((:name . "Ana")))
"Hello Ana!"

Использование в качестве словаря hash-table:

CL-USER> (let ((user (make-hash-table)))
           (setf (gethash :name user)
                 "Ana")
           (examples.simple:hello-name user))
"Hello Ana!"

или

CL-USER> (let ((user (make-hash-table :test 'equal)))
           (setf (gethash "NAME" user)
                 "Ana")
           (examples.simple:hello-name user))
"Hello Ana!"

Использование в качестве словаря объекта CLOS:

CL-USER> (defclass user () ((name :initarg :name)))
#<STANDARD-CLASS USER>
CL-USER> (examples.simple:hello-name (make-instance 'user :name "Ana"))
"Hello Ana!"

Интеграция с ASDF¶

cl-closure-template также реализует расширение ASDF, которое позволяет указывать файлы шаблонов Closure Template при описании системы. При загрузке системы указанные файлы шаблонов будут компилироваться с помощью Common Lisp backend-а. По-умолчанию, считается, что файлы с шаблонами имеют расширение ".tmpl".

Пример:

(defsystem #:cttest
  :defsystem-depends-on (#:closure-template)
  :components ((:closure-template "template1")
               (:closure-template "template2" :type "soy")))

Важно что бы расширение, реализуемое cl-closure-template, было доступно ещё до обработки описания системы, поэтому здесь зависимость от cl-closure-template описывается в секции :defsystem-depends-on, а не в секции :depends-on. Подробности здесь: http://common-lisp.net/project/asdf/asdf/The-defsystem-grammar.html.

Компиляция шаблонов с помощью SLIME¶

В состав исходного кода cl-closure-template так же входит closure-template-html-mode.el - режим для Emacs, который обеспечивают базовую подсветку и выравнивание кода. При редактировании в Emacs файла с шаблонами Closure Templates в этом режиме доступна команда closure-template-compile, которая пытается скомпилировать редактируемый файл для Common Lisp backend с помощью SLIME. По-умолчанию, данная команда доступна с помощью биндинга C-c C-l. Для успешной компиляции необходимо что бы cl-closure-template была загружена в SLIME.
