Compiler Backends¶

cl-closure-template имеет один frontend для парсинга шаблонов и строительства промежуточного представления и несколько backend-ов для поддержки различных языков программирования. В данный момент доступны следующие backend-ы:

  • JavaScript Source backend (:javascript-backend) для использования Closure Templates в JavaScript. Данный backend компилирует файлы с шаблонами в JavaScript-код. Для каждого пространства имён создаётся отдельный объект-словарь, а шаблоны становятся функциями-свойствами данного объекта с такими же именами.

  • JavaScript RequireJS Source backend. Отличается от "" тем, что выходной код может быть использован совместно с RequireJS.

  • Common Lisp backend поддерживает использовать Closure Templates в Common Lisp. Данный backend для каждого пространства имён создаёт отдельный package, а шаблоны становятся функциями и связываются с символами в данном package. При этом, все используемые имена проходят процедуру "лиспификации", например шаблон с именем helloWorld становится функцией hello-world.

Модель данных¶

cl-closure-template использует универсальную модель данных, что позволяет использовать одни и те же шаблоны как в JavaScript, так и в Common Lisp. Для структуризации данных могут использовать словари и списки. Ключи словаря должны быть идентификаторами (т.е. можно использовать буквы, цифры и символ подчёркивания). Так же поддерживаются 5 примитивных типов: null, boolean, integer, float, и string.

Каждый backend имеет собственные представления о том, как данные должны передаваться в шаблон. Для примера, рассмотрим шаблон, который принимает два параметра: name - имя человека и destinations - список городов, в которые он недавно ездил.

В JavaScript можно использовать любой JavaScript-объект, например:

var data = {name: 'Melissa', destinations: ['Singapore', 'London', 'New York']};

В Common Lisp в качестве входных данных шаблона можно использовать разные типы данных, для которых должны быть определены специализации generic-функций closure-template:fetch-property и closure-template:fetch-keys. Библиотекой поддерживаются plist, alist или hash-table, при этом, в качестве ключей можно использовать как keyword-символы, так и их строковое представление (например, для параметра шаблона additionalName можно использовать :additional-name или "ADDITIONAL-NAME").

(list :name "Melissa"
      :destinations '("Singapore" "London" "New York"))

Структура файлов¶

Каждый файл с шаблонами должен иметь, как минимум, два компонента:

  • Декларацию пространства имён

  • Определение одного или нескольких шаблонов.

Декларация пространства имён¶

Файл с шаблонами должен иметь единственное определение пространства имён. Корректным именем пространства имён является один или несколько идентификаторов, соединённых с помощью точки. Например:

{namespace examples.simple}

Определение шаблонов¶

Один или несколько шаблонов определяются после декларации пространства имён, по одному тэгу template на каждый шаблон. Вы должны использовать уникальные имена для каждого шаблона. Тело шаблона размещается между тэгом template и соответствующим тэгом /template. Например:

{template helloName}
   Hello {$name}
{/template}

Синтаксис команд¶

Команды это инструкции на основе которых определяется логика шаблонов. Команды определяется с помощью Closure Template тэгов, выделяемых фигурными скобками ({}). Первый токен в тэге это имя команды (если имя не указано, то считается что это команда print). Если команда имеет соответствующий закрывающий тэг, то он помечается с помощью / расположенного перед именем в начале команды, например foreach и /foreach.

Описание всех команд смотрите в разделе Команды.

Выражения¶

Вы можете использовать в шаблонах выражения для ссылок на данные шаблоны или переменные. Closure Templates использует независимый от языка синтаксис выражений. В этом разделе описывается, как обращаться к данным, создавать литералы для всех примитивных типов, а также использовать основные операторы.

Использование параметров или переменных¶

Для обращения к параметрам шаблона используется знак $ и имя параметра после него, например, $userName. Для обращения к вложенным данным можно соединить несколько ключей с помощью точки. Например, выражение $folders.0.name вычисляется как значение с ключом name первого объект параметра folders. Однако, это вычисление будет успешным только в том случае, если folders не пустой список или словарь, а его первый элемент это словарь, содержащий ключ name. Это выражение можно записать также как $folders[0].name или $folders[0]['name'].

Специальный префикс $ij используется для доступа к внедрённым данным, которые автоматически передаются во все вызываемые шаблоны. Для примера, $ij.foo ссылается на внедрённый параметр foo.

Некоторые команды создают локальные переменные, на которые ссылаются так же, как и на параметры шаблона. Таким образом, обращение $user.email корректно когда user это параметр шаблона или локальная переменная.

Основные типы¶

Тип Литерал
Null null
Boolean false или true
Integer Десятичный (например, -827) или шестнадцатеричный (должен начинаться с 0x и использовать буквы A-F, например, 0x1A2B).
Float

Должен быть в десятичной систем, а также:

  • Иметь цифры как слева, так и справа от точки, например, 0.5, -100.0, 0.0, или

  • Иметь букву e для обозначения научного формата, например, -3e-3, 6.02e23.
String Выделяется одинарными кавычками. Можно использовать escape-последовательности: \\, \', \", \n, \r, \t, \b, \f и \u####, где #### могут быть 4 любых шестнадцатеричных символа обозначающих символ Unicode.
List
[<expr1>, <expr2>, ...]
Например: [1, 'two', [3, false]]
[] - пустой список
Map
{<keyExpr1>: <valueExpr1>, <keyExpr2>: <valueExpr2>, ...}
Например: {'aaa': 42, 'bbb': 'hello'}
{:} - пустой словарь

Операторы¶

Поддерживаются следующие операторы, перечисленные в порядке убывания приоритета (самый высокий приоритет в верхней части):

  • - (унарный) not

  • * / %

  • + - (бинарный)

  • < > <= >=

  • == !=

  • and

  • or

  • ?: (бинарный) ? : (тернарный)

Оператор + предназначен для сложения чисел или объединения строк. Если один из двух операндов является строка, то другое значение приводится строке. Все примитивные значения имеют строковые представления. Строковое представление словаря и списка не определены.

Оператор / выполняет деление с плавающей точкой. Для операций целочисленного деления используйте функции floor и ceiling вместе с делением.

Когда не-булево значение используется в булевом выражении, оно приводится к булеву. Каждый примитивный тип имеет ровно одно "ложное" значения: null это всегда "ложь", false "ложь" для булевых значений, 0 является "ложью" для целых, 0.0 "ложь" для чисел с плавающей точкой, '' (пустая строка) "ложь" для строк. Все остальные значения примитивных типов являются "истиной". Значения списков и словарей всегда "истинны", даже если они не имеют элементов.

Функции¶

Так же в выражениях можно использовать несколько простых функций. Список доступных функций приведён в разделе Функции и директивы печати.

Внедрённые данные¶

Внедрённые данные доступны в каждом шаблоне, их не нужно руками передавать в вызываемые шаблоны.

Для шаблона:

{namespace ns}

{template example}
   foo is {$ij.foo}
{/template}

В JavaScript можно внедрить данные с помощью третьего параметра

output = ns.example(
  {},  // data
  null,  // optional output buffer
  {'foo': 'injected foo'})  // injected data

В Common Lisp внедрение данных происходит с помощью специальной переменной closure-tempate:*injected-data*:

(let ((*injected-data '(:foo "injected foo")))
  (ns:example nil))

Пример использования внедрённых данных:

{namespace ns}

{template example}
   {call helper /}
{/template}

{template helper}
   foo is {$ij.foo}
{/template}

Комментарии¶

Комментарии в шаблонах имеют синтаксис, традиционный для C-подобных языков:

  • // - однострочный комментарий

  • /* comment */ - многострочный комментарий

Комментарии игнорируются всеми backend-ами и не оказывают какого-либо влияния на результат.

Простой текст¶

Весь текст в шаблоне, включая HTML-тэги, не окружённый фигурными скобками, считается "сырым" текстом. cl-closure-template удаляет лишние пробельные символы в таком тексте, но не пытается его анализировать, а просто добавляет в результат работы шаблона.
